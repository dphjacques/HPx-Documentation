Using Numpy, scipy, pandas in HPx

Example for numpy - similar for scipy, pandas


1. Install numpy into a user folder using Anaconda's pip with -- target:


       User folder - for example "Directory for configuration files and programs settings" or "Folder for HPx data"

       see HYDRUS5.x ->Options->Program Options->Files and Directories


Here, the first folder is selected ("C:\Users\djacques\OneDrive - Studiecentrum voor Kernenergie\Documents\PC-Progress\HYDRUS 5.x\Settings\HP\packages")


Open an Anaconda prompt and run:


conda activate py38

pip install numpy --target "C:\Users\djacques\OneDrive - Studiecentrum voor Kernenergie\Documents\PC-Progress\HYDRUS 5.x\Settings\HP\packages"



2. Copied all DLLs from numpy\.libs into numpy\core  (this can be run from HPx (only once) and also python38.dll


import sys

import os

import shutil


numpy_core = r"C:\Users\djacques\OneDrive - Studiecentrum voor Kernenergie\Documents\PC-Progress\HYDRUS 5.x\Settings\HP\packages\numpy\core"

numpy_libs = r"C:\Users\djacques\OneDrive - Studiecentrum voor Kernenergie\Documents\PC-Progress\HYDRUS 5.x\Settings\HP\packages\numpy\.libs"


for f in os.listdir(numpy_libs):

    if f.endswith(".dll"):

        shutil.copy(os.path.join(numpy_libs, f), numpy_core)

        print("Copied:", f)


#IUse here the folder where HPx.exe is installed

shutil.copy(r"D:\PC-Progress\HYDRUS 5.06 64-bit\Bin\HPx\Bin\python38.dll", numpy_core)   

print("Copied python38.dll")


3. Add the package folder to sys.path at the top of the script:


import sys

packages_dir = r"C:\Users\djacques\OneDrive - Studiecentrum voor Kernenergie\Documents\PC-Progress\HYDRUS 5.x\Settings\HP\packages"

sys.path.insert(0, packages_dir)


import numpy as np




The key point is to place all dlls right to the .pyd file (so, Windows find them without problems).

So:


The .pyd file that fails is always mentioned in the error message. For numpy, this could be:

_multiarray_umath.cp38-win_amd64.pyd

found in numpy\core\.

The pattern will be the same:

look at the error message which will say something like:

DLL load failed while importing _somemodule


That _somemodule is the name of the .pyd file. For example:

  • scipy might give _fitpack.cp38-win_amd64.pyd in scipy\interpolate\
  • pandas might give _libs\hashtable.cp38-win_amd64.pyd in pandas\_libs\

The general rule is:

  1. The .pyd file has the same name as the failing module in the error
  2. It is always in the subfolder matching the import path shown in the stack trace
  3. Copy the DLLs from that package's .libs folder (e.g. scipy\.libs) into the same folder as the .pyd file
